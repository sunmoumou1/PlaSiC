# 2.7 Robert–Asselin Filtering { #robertasselin }

This note continues the time-level notation of the dynamical-core entry note
([2.1 Governing Equations](<2.1-governing-equations.md>); the discrete form of that notation is
collected in [2.2 Ten-Step Algorithm](<2.2-ten-step-algorithm.md>)).

This note explains how the Robert–Asselin filter damps the computational mode of that scheme and
completes the rotation of the time levels.

## Robert–Asselin time filtering { #robert-asselin-filter }

The dynamical core applies the Robert–Asselin filter to the middle time level (Asselin, 1972):

$$
\widetilde X^j
=X^j+\nu
\left(X^{j-1}-2X^j+X^{j+1}\right),
\tag{2.7.1}
$$

that is,

$$
\widetilde X^j
=\nu X^{j-1}+(1-2\nu)X^j+\nu X^{j+1}.
$$

When the filter is applied step after step, the old-level term is the already filtered value
\(\widetilde X^{j-1}\). The code takes advantage of this by forming the first two terms early and
adding the last term \(\nu X^{j+1}\) once the complete new level is available (Step 10 of
[2.2 Ten-Step Algorithm](<2.2-ten-step-algorithm.md>)).

The reason the filter works can now be read off directly. Recall from
[2.6 Leapfrog Time Stepping](<2.6-leapfrog-time-stepping.md#computational-mode>) that the leapfrog
solution splits into a smooth physical part and a computational mode \(a(-1)^j\) that flips sign at
every step. If the physical solution varies smoothly in time, then
\(X^{j-1}-2X^j+X^{j+1}=O(\Delta\tau^2)\) and the correction is small. For a physical
mode of frequency \(\omega\), write \(X^j=Ae^{\mathrm i\omega j\Delta\tau}\); a real cosine mode is
the real part of this expression, and because the filter is linear with real coefficients, that
real part obeys the same relation. With \(\theta=\omega\Delta\tau\),

$$
X^{j\pm1}=e^{\pm\mathrm i\theta}X^j,
$$

so the second difference becomes

$$
X^{j-1}-2X^j+X^{j+1}
=\left(e^{-\mathrm i\theta}-2+e^{\mathrm i\theta}\right)X^j
=2(\cos\theta-1)X^j
=-4\sin^2\!\left(\frac{\theta}{2}\right)X^j
=-4\sin^2\!\left(\frac{\omega\Delta\tau}{2}\right)X^j,
$$

where the last step uses the half-angle identity \(1-\cos\theta=2\sin^2(\theta/2)\). For a
well-resolved mode \(\sin(\theta/2)\approx\theta/2\), so this is approximately
\(-(\omega\Delta\tau)^2X^j\). One filter application therefore changes the physical amplitude by
the factor
\(1-4\nu\sin^2(\omega\Delta\tau/2)\approx1-\nu(\omega\Delta\tau)^2\), which stays close to one for
well-resolved frequencies. 

For the computational mode \(a(-1)^j\), the second difference is not
small at all:

$$
a(-1)^{j-1}-2a(-1)^j+a(-1)^{j+1}
=-4a(-1)^j,
$$

because the mode flips sign at every step. A single application of the Robert–Asselin filter
therefore reduces the amplitude of this mode at the middle time level from \(a\) to approximately
\((1-4\nu)a\). The filter reacts strongly to the step-by-step sign alternation and only weakly to
the smooth physical solution, so it gradually pulls the odd and even time chains together.

The price is that the physical solution also suffers a small amount of numerical damping and phase
error, and the RA filter reduces the formal time accuracy of the leapfrog scheme from second order
to first order. The filter weight \(\nu\) must therefore stay small; it is usually chosen between
about \(0.01\) and \(0.2\) (Asselin, 1972, examined values up to \(0.2\)). In PlaSiC the weight is
the planetary constant `plasic_pnu`, whose default is \(0.1\) (see
[1.3 Global State Variables](<../1-user-guide/1.3-global-state-variables.md>)). For this cost and
for improved filters, see Williams (2009) and Amezcua et al. (2011).

If only one time level is available at the start, the usual approach is to begin with a few short
forward steps and then switch to the centered leapfrog (start-up procedures are described by
Robert, 1966, and Durran, 2010).
