# 1.2 Pseudocode for One Time Step { #plasic-run-pseudocode }

This note answers only one question: "how does the program run?" If you have just received the code,
read this piece first to build a global impression, then return to Chapters 2, 3, and 4 as your
interests lead you to look up formulas and principles.
The model is an independent C implementation of PlaSim (Fraedrich et al., 2005); the numerical
schemes referenced below are those described in Chapters 2–4.

!!! tip "Five sentences to remember first"

    1. Global state is centralized in `src/state/plasicmod_state.c`, and arrays are flattened in a
       column-major layout where horizontal grid points within the same vertical level are stored contiguously;
    2. One time step always consists of four segments: **adiabatic grid points → adiabatic spectral advance → physics parameterization → spectral closure and dissipation**;
    3. The dynamical core and the physical processes exchange only tendencies (the `*t` spectral arrays); physical processes never update the prognostic variables directly;
    4. Land surface, sea ice, and ocean are all called in a fixed order inside `plasic_physics_step()`, coupled through shared grid-point arrays;
    5. Configuration has four layers: compile-time macros, code defaults, runtime command line/JSON, and external data files.

## 1. Pseudocode for One Time Step (Overview)

The body of `plasic_runtime_run()` is a single loop, each iteration advancing one dynamical time
step \(\Delta\tau\). The complete skeleton is written below in pseudocode; the following sections
expand it segment by segment.

```text
# At loop start
for step in 0 .. options.steps - 1:

    step2cal(plasic_calendar, nstep, ndatim)  # model step -> year/month/day/hour/minute
    runtime_co2_forcing_apply(year, month)  # update the CO2 field in the radiation module

    # ── Stage 1: adiabatic grid-point computation (spectral -> grid -> explicit tendency -> spectral) ──
    runtime_gridpoint_adiabatic()

    # ── Stage 2: adiabatic spectral advance (semi-implicit gravity waves + leapfrog, Robert–Asselin) ──
    runtime_spectral_adiabatic()

    # ── Stage 3: physics parameterization (spectral -> dimensional grid -> physics tendency -> spectral) ──
    runtime_gridpoint_diabatic(options.dynamics_only)

    # ── Stage 4: spectral closure (add physics and dissipation to obtain time level j+1) ──
    runtime_spectral_diabatic()

    if state contains NaN/Inf: stop integration   # runtime_state_is_finite()

    if not dynamics_only:
        runtime_accumulate_output_fields()    # accumulate diagnostics such as precipitation, fluxes, cloud cover
        runtime_monthly_netcdf_accumulate()

    ++plasic_nstep                          # only now is the j+1 state complete
    step2cal(plasic_calendar, nstep, ndatim) # calendar at the new time
    runtime_write_step_outputs()            # JSONL progress + (by frequency) frame output

# After the loop ends
runtime_monthly_netcdf_close()
runtime_close_step_outputs()
```

All four stages are defined in `src/runtime/runtime_dynamics.c`. They do no numerical computation
themselves; instead they assemble, in the correct order, the operators from `src/dynamical_core/`,
`src/math_tools/`, and `src/physics/`.

Note that `++plasic_nstep` is at the end of the loop: the calendar, solar position, and CO2 forcing
for the whole step are taken from the "old time level j", and the model clock advances only after
the j+1 state is complete and has passed the check.

## 2. From `main` to the Main Loop: What Initialization Does

The lifecycle of an executable lives in `src/app/plasic_cli.c`: parse arguments, call the runtime,
write the restart. The runtime's public interface is just the five functions in
`src/plasic_runtime.h`:

```text
main(argc, argv)                             # src/app/plasic_standalone.c
└─ plasic_cli_run()                          # src/app/plasic_cli.c
   ├─ options = code defaults                # plasic_runtime_options
   ├─ if --config: plasic_config_load()      # src/plasic_config.c (JSON)
   ├─ parse command-line arguments, overriding options   # priority: CLI > JSON > defaults
   ├─ plasic_runtime_initialize(options)     # src/runtime/plasic_runtime.c
   │   ├─ validate options; mp_start()       # src/mpi/
   │   ├─ plasic_state_init()                # global state and constants
   │   ├─ runtime_initialize_dynamics()      # resolution-dependent static numerical environment
   │   │   ├─ planet_defaults()              # planetary constants (Earth defaults)
   │   │   ├─ calmod_init(ntspd)             # register steps-per-day with the calendar module
   │   │   ├─ gauss_inigau()/inilat()        # Gaussian latitudes, weights, and spherical metric factors
   │   │   ├─ initpm_vertical()              # σ-level interfaces, layer thickness, and reciprocals
   │   │   ├─ initpm_spectral()/initsi()     # dissipation rates, reference temperature, vertical operators
   │   │   ├─ makebm()                       # inverse of the semi-implicit matrix M_n
   │   │   └─ sht_init()                     # SHTns transform plan
   │   ├─ cold start: cal2step()             # --calendar + --start-* -> nstep
   │   ├─ runtime_load_atmosphere_restart()  # warm start: nstep + calendar from the file
   │   ├─ --reset-nstep (warm start only)    # rebase nstep and print the new date
   │   ├─ step2cal()                         # nstep + calendar -> plasic_ndatim
   │   ├─ runtime_prepare_orography_grid()   # synthesize orography spectra onto the grid
   │   ├─ plasic_physics_initialize()        # land/ocean/sea-ice/radiation state
   │   └─ open CO2 forcing, monthly-mean NetCDF, progress stream, and frame stream
   ├─ plasic_runtime_run(options)            # the main time-integration loop from the previous section
   ├─ plasic_runtime_write_restart()         # write the final restart
   └─ plasic_runtime_finalize()              # release all resources
```

The initialization order cannot be changed arbitrarily: the spherical-harmonic transform plan and
spectral partitioning must precede the restart read (the restart array layout depends on the
compile-time resolution); the physical spheres must be initialized only after the atmospheric
state, orography, and calendar are ready. There is also an easily overlooked step in
initialization: after synthesizing the orography, correct the reference surface pressure
`plasic_psurf` using the global-mean mode of the spectral orography, so that the higher the mean
orography, the lower the reference pressure.

## 3. The Four Stages in Detail

### 3.1 Stage 1: Adiabatic Grid-Point Computation

`runtime_gridpoint_adiabatic()` transforms the current spectral state to the Gaussian grid,
computes the nonlinear adiabatic terms, and analyzes them back to spectral space. This is the most
computationally expensive step in the dynamical core; its main blocks are:

1. **Spectral → grid synthesis** (`synthesize_adiabatic_fields()`; transforms via SHTns, Schaeffer, 2013):
    - `sht_vortdiv_to_wind()` inverts the Robert winds \(U=u\cos\phi\), \(V=v\cos\phi\) from absolute vorticity and divergence;
    - `sht_scalar_to_grid()` synthesizes divergence, temperature, vorticity, mass-weighted humidity \(\chi=(p_s/p_0)q\), and the log pressure ratio \(\pi=\ln(p_s/p_{surf})\);
    - `sht_scalar_to_grid_gradient()` directly synthesizes the two horizontal derivatives of \(\pi\).

2. **Recover the pressure ratio**: `exp_array()` computes \(p_s/p_{surf}=e^{\pi}\).

3. **Grid-point nonlinear adiabatic terms** (`calcgp()`, `src/dynamical_core/calgp.c`):
    - recover specific humidity \(q\), temperature \(T\), and virtual temperature \(T_v\) from \(\chi\), \(e^{\pi}\), and \(T'\);
    - compute the surface pressure advection \(P=v_h\cdot\nabla\pi\) and the mass divergence \(A=D+P\); integrate \(A\) over the whole column to obtain \(\bar{A}=\sum_k\Delta\sigma_kA_k\) for the \(\dot{\sigma}\) diagnostic, while retaining the explicit surface-pressure contribution \(\bar{A}_{\rm exp}=\sum_k\Delta\sigma_kP_k\) for spectral analysis;
    - construct \(\dot{\sigma}\) level by level: \(\dot{\sigma}_{k+1/2}=\sigma_{k+1/2}\bar{A}-\sum_{j\le k}\Delta\sigma_jA_j\);
    - build the vertical transport terms for temperature, momentum, and water vapor from \(\dot{\sigma}\) and the differences between adjacent levels;
    - output the grid-point source terms and fluxes used for spectral analysis (temperature source, water-vapor vertical source, \(U/V\) momentum fluxes, etc.), and diagnose \(\omega/p\) and the moist virtual geopotential correction.

4. **Nonlinear flux products** (`gridpointa_products()`): combinations such as \(uT\), \(vT\), \(uq\), \(vq\), and kinetic energy plus geopotential.

5. **Grid → spectral analysis**: the surface pressure tendency is analyzed as a single level with
   `sht_grid_to_scalar()`; momentum/temperature use `sht_mktend()` and humidity uses `sht_qtend()`,
   yielding the complete spectral tendency; `extract_local_spectral_block()` then slices it into the current
   rank's local blocks `spt/sdt/stt/szt/sqt`.

6. **Physics snapshot**: `gridpointa_snapshots()` copies the dimensional surface pressure and wind
   field into `dp0/du0/dv0` for the physics parameterization that follows immediately.


### 3.2 Stage 2: Adiabatic Spectral Advance

`runtime_spectral_adiabatic()` completes the adiabatic time advance in spectral space, in three
steps:

1. `spectrala_implicit()`: for each total wavenumber \(n\), solve the vertically coupled equation
   \(M_n\bar{D}_n=b_n\), where \(M_n^{-1}\) was precomputed at initialization by `makebm()`.
   The semi-implicit treatment handles the fast-propagating gravity waves so the time step need not
   be very small (Kwizak & Robert, 1971; Hoskins & Simmons, 1975);
2. `spectrala_finalize()`: leapfrog update
   \(X^{j+1}=X^{j-1}+2\Delta\tau R_X^j\), with divergence using the time-centered value
   \(D^{j+1}=2\bar{D}-D^{j-1}\); then apply the Robert–Asselin filter (Robert, 1966; Asselin, 1972) and update the local arrays
   `spp/sdp/szp/stp/sqp` and the old-level arrays `spm/sdm/szm/stm/sqm`;
3. `gather_current_spectral_state()`: gather the local spectral blocks `*p` from each rank into the
   complete spectral fields `sd/sz/st/sp/sq` for use by the next synthesis and by the physics.

### 3.3 Stage 3: Physics Parameterization

`runtime_gridpoint_diabatic()` is the bridge between the dynamical core and the physics modules. It
first clears the tendency buffers, then follows the chain below:

```text
adiabatic spectral state
  -> spectral synthesis to the grid (only wind, temperature, humidity, and surface pressure are needed)
  -> recover dimensional state: ps = p0 exp(gp), (u,v) = cv(gu,gv)/cosφ, T = ct(gt+T0), q = gq p0/ps
  -> plasic_physics_step() accumulates du/dt, dv/dt, dT/dt, dq/dt
  -> gridpointd_tendencies() converts back to dimensionless grid-point tendencies
  -> sht_grid_to_scalar()/sht_wind_to_vortdiv() analyze into physics spectral tendencies
  -> extract_local_spectral_block() slices into local *t for use by Stage 4
```

The fixed calling order of the physics parameterizations is written in `physics_step()` in
`src/physics/physics_processes.c`:

| Order | Function | Purpose | Main output |
|---|---|---|---|
| 1 | `moisture_fixer()` | mass/moisture consistency correction (enabled by default) | `gqdt` correction |
| 2 | `surface_fluxes()` | surface exchange coefficients and fluxes: `flux_surface_exchange_coefficients`, `flux_mkstress`, `flux_mkshfl`, `flux_mkevap` | `dudt/dvdt/dtdt/dqdt`, `dtaux/dtauy`, `dshfl/dlhfl/devap` |
| 3 | `vertical_diffusion_step()` | boundary-layer vertical diffusion: `vdiff`, redistributing momentum, heat, and moisture among model levels | diffusive contributions to `dudt/dvdt/dtdt/dqdt` |
| 4 | `radiation_step()` | solar geometry, ozone, shortwave, longwave, and heating rates | `dtdt`, `dswfl/dlwfl/dflux` |
| 5 | `rain_step()` | Kuo convection, dry adjustment, large-scale condensation, rain/snow fallout, cloud cover | `dtdt/dqdt`, `dprc/dprl/dprs`, `dcc/dql` |
| 6 | `land_step()` | land temperature and snow (`land_tands`), soil water, surface exchange, glaciers | land state, `dt/dq` surface level, `dalb/dwetfac/dz0` |
| 7 | `sea_step()` | accumulate sea-surface fluxes; call `ice_step()` and `ocean_step()` at coupling times; refresh the sea-surface boundary | sea-ice/ocean state, `dt/dq` surface level, `dalb/dz0` |

When `dynamics_only != 0`, the entire `plasic_physics_step()` is skipped. Because the tendencies
have already been zeroed, the final physics spectral tendency is zero, but the state conversion and
spherical-harmonic analysis workflow are still carried out in full.

Scheme sources for this table: surface fluxes and vertical diffusion follow Louis (1979; see also
Blackadar, 1962); radiation follows Lacis and Hansen (1974) and Sasamori (1968); the moist physics
follows Kuo (1965, 1974), Tiedtke (1983), and Slingo and Slingo (1991); the land surface follows
Manabe (1969); and the thermodynamic sea ice follows Semtner (1976). The corresponding notes in
Chapters 3 and 4 give the equations and the full reference lists.

### 3.4 Stage 4: Spectral Closure

`runtime_spectral_diabatic()` combines the adiabatic candidate state, the physics tendency, and
numerical dissipation into the final state:

1. `spectrald_add_physics()`: \(X_{candidate}=X_{adiabatic}+2\Delta\tau R_{physics}\);
2. `spectrald_dissipation()`: Newtonian relaxation of temperature toward the reference profile,
   Rayleigh friction of divergence and relative vorticity, scale-selective spectral diffusion of
   temperature/humidity/divergence/vorticity (Laursen & Eliasen, 1989; Held & Suarez, 1994), and a sponge layer at the model top. The damping uses
   a semi-implicit form with a denominator, in which `plasic_Lnkpp` makes high-wavenumber modes
   decay more strongly;
3. `spectrald_finalize()`: add the damping tendency, complete the leapfrog update and
   Robert–Asselin filter, and obtain the complete j+1 state;
4. `gather_current_spectral_state()`: once again gather the local spectral blocks into the complete
   spectral fields.

After Stage 4, wind, temperature, and humidity have their complete j+1 state; surface pressure no
longer changes during the physics and spectral-dissipation stages (it is advanced only in the
adiabatic mass equation earlier), but it still takes part in the Robert–Asselin time filter (see
[2.5 Semi-implicit gravity wave solve](<../2-dynamical-core/2.5-semi-implicit-gravity-wave-solver.md>) and
[2.7 Robert–Asselin filtering](<../2-dynamical-core/2.7-robert-asselin-filtering.md>)).

## 4. How Coupling Is Done

There is no separate coupler object in the code: the spheres exchange variables through `plasic_*`
shared grid-point arrays, and the calling order is the coupling order. Within one physics step:

```text
atmospheric dimensional grid state (dp, du, dv, dt, dq) and the old surface boundary
  └─ surface_fluxes()            this step's fluxes are written immediately into dudt/dvdt/dtdt/dqdt and take effect this step
  └─ vertical_diffusion_step()   turbulent mixing between model levels, continuing to adjust atmospheric tendencies
  └─ radiation_step()            update atmospheric heating rates and, at the same time, boundaries such as dalb
  └─ rain_step()                 precipitation goes into dprl/dprc/dprs for consumption by land and sea
  └─ land_step()                 update land state, write back dt[surface], dq[surface], dwetfac, dalb, dz0
  └─ sea_step()                  accumulate fluxes -> ice_step() -> ocean_step() -> sea_update_surface()
  -> Stage 4 adds this step's physics tendency to the atmospheric spectral state
```

Three key rules:

1. **This step's fluxes, next step's boundaries**: fluxes computed in this step immediately form
   atmospheric tendencies; the boundary conditions derived from the new land/sea-ice/ocean states
   (surface temperature, moisture factor, albedo, roughness) usually begin to feed back from the
   next atmospheric step;
2. **Land–sea split**: horizontal grid points are routed by the land–sea mask `dls`; land points go
   only through `land_step()` and ocean points only through `sea_step()`;
3. **Sea ice in the middle**: atmospheric fluxes are first accumulated by `sea_step()` and passed to
   `ice_step()`; sea ice then transfers heat, freshwater, and stress to `ocean_step()`; the SST,
   mixed-layer depth, and heat fluxes returned by the ocean are converted through the sea-surface
   interface into boundaries usable by the atmosphere. Inside `ocean_step()`, the three-dimensional
   deep ocean is advanced first, and then the forced single-layer mixed layer is updated; the slab
   itself has no vertical or horizontal diffusion.

For a more complete list of fluxes, return values, and a timing table of when they take effect, see
[4.1 How the spheres are coupled](../4-model-and-coupling/4.1-how-the-spheres-are-coupled.md).

## 5. Where Configuration Comes From

Configuration has four layers, stacked in order of "the later, the higher the priority".

### 5.1 Compile time: `src/Makefile` macros

Resolution, number of levels, number of processes, and ocean model are all decided at compile time
and passed into the C code through `-D` macros:

| Makefile variable | Default | Purpose |
|---|---|---|
| `NLAT` | 48 | number of latitudinal grid points; longitudinally `NLON = 2*NLAT` |
| `NLEV` | 13 | number of atmospheric vertical levels |
| `NPRO` | 1 | number of MPI processes (effective when `MPI=1`) |
| `MPI` | 0 | 0 uses the serial backend, 1 uses native MPI |
| `OCEAN_MODEL` | 3d | `slab` or `3d` ocean |
| `DEEP_OCEAN_LEVELS` | 16 | number of vertical levels in the 3D ocean |

`src/state/plasicmod_state.h` then derives all array dimensions from them, for example

$$
\text{NLON}=2\text{NLAT},\qquad
\text{NTRU}=\frac{\text{NLON}-1}{3},\qquad
\text{NRSP}=(\text{NTRU}+1)(\text{NTRU}+2).
$$

**The restart file must exactly match the
compile-time resolution**, otherwise `runtime_load_atmosphere_restart()` fails immediately during
the dimension check.

### 5.2 Code defaults: constants and physics switches

- Planetary constants: `planet_defaults()` in `src/tools/p_earth_kernels.c` (sidereal day, solar day,
  \(\kappa\), gas constant, Robert–Asselin weight, gravity, planetary radius);
- State defaults: `plasic_state_init()` in `src/state/plasicmod_state.c` (reference temperature `tgr`,
  reference pressure `psurf`, melting temperature `tmelt`, spectral diffusion time scales `tdiss*`, etc.);
- Time step and calendar: `runtime_initialize_dynamics()` selects the number of minutes `mpstep`
  according to `NLAT`, then takes an even number of steps to obtain `ntspd`, so that
  \(\Delta t=\text{solar day}/\text{ntspd}\); the calendar kind itself comes from `--calendar`
  (cold start) or from the restart file (`tools/calmod_kernels.c`); some level counts (e.g. 10
  levels) also have a dedicated low-level friction time scale;
- Physics switches and tuning: set per module in `src/physics/physics_initialization.c`, for example
  the vertical-diffusion/sensible-heat/evaporation/stress switches and stability coefficients in
  `initialize_flux()`, the convection, dry-adjustment, large-scale condensation, and cloud-cover
  switches in `initialize_rain()`, and the solar constant, cloud tuning, and ozone parameters in
  `initialize_radiation()`.

Changing these values requires recompilation, and they usually have no CLI switches; comments in
the source code are often the only documentation.

### 5.3 Runtime: `plasic_runtime_options`

Runtime configuration is unified into the `plasic_runtime_options` structure in
`src/plasic_runtime.h`, which is used after validation by `plasic_runtime_initialize()`:

| Field | Meaning |
|---|---|
| `restart_input` | input restart; cold start when `NULL` |
| `surface_data_directory` | surface data directory for cold start |
| `restart_output` | restart output path at the end |
| `progress_output` / `frame_output` | progress record stream / binary frame stream |
| `co2_forcing_input` or `co2_ppm` | choose either CO2 forcing method |
| `monthly_output_directory` | monthly-mean NetCDF output directory |
| `steps` / `frame_interval` / `progress_interval` | number of steps and output intervals |
| `calendar` | calendar kind for a cold start: 0 = Gregorian, 1 = 12 × 30-day |
| `start_year` / `start_yday` / `start_hour` / `start_minute` | cold-start date (year 0-based, day-of-year 1-based) |
| `reset_nstep` | warm start only: replace the `nstep` read from the restart, negative = not requested |
| `dynamics_only` | dynamics only, skip physics parameterization |

Both entry points write into this structure:

- JSON file: `plasic_config.c` parses same-named fields such as `restart`, `data_dir`, `output`,
  `steps`, `calendar`, `start_year`, `start_yday`, `reset_nstep`, `co2_ppm`, and `dynamics_only`,
  specified by `--config FILE`;
- Command line: `--restart`, `--data-dir`, `--steps`, `--output`, `--calendar`, `--start-year`,
  `--start-yday`, `--start-hour`, `--start-minute`, `--reset-nstep`, `--co2-forcing`,
  `--dynamics-only`, etc. in `plasic_cli.c`. The CLI scans in two passes, loading `--config` first
  and then parsing the remaining arguments, so the priority is **CLI > JSON > code defaults**. The
  desktop application `plasic_app` ultimately calls the same runtime interface (see
  [8.1 PlaSiC App Architecture Guide](../8-desktop-app/8.1-plasic-app-architecture-guide.md)).

### 5.4 External data files

| Data | Location / entry point | Purpose |
|---|---|---|
| initial restart | `src/data/earth_*.restart` or `--restart` | warm-start the atmosphere and physical sphere states |
| surface data | `data/surface` (`--data-dir`) | NetCDF fields such as orography, albedo, and roughness for cold start |
| CO2 forcing | `data/forcing/CO2/*.csv` or `--co2-ppm` | monthly zonal-band CO2 or a fixed concentration |
| output restart | `--output` (default `status`) | continuation runs and archiving |

## 6. Array Naming Quick Reference

Reading the code means dealing with a great many flattened arrays; memorizing this naming scheme
will save a lot of time:

| Notation | Meaning | Example |
|---|---|---|
| prefix `s` | spectral-space quantity | `sz` absolute vorticity, `sd` divergence, `st` temperature, `sq` mass-weighted humidity, `sp` log surface pressure, `so` spectral orography |
| suffix `p` | this rank's **current** local spectral block | `sdp`, `szp`, `spp` |
| suffix `m` | leapfrog **old-time-level** local spectral block | `sdm`, `szm`, `spm` |
| suffix `t` | local spectral **tendency** | `sdt`, `szt`, `stt`, `sqt` |
| prefix `g` | dimensionless grid-point field | `gu/gv` Robert winds, `gt` temperature perturbation, `gq` mass-weighted humidity, `gd/gz` divergence/vorticity, `gp` log pressure ratio |
| prefix `d` | dimensional grid-point field or diagnostic | `dp` pressure, `du/dv` wind, `dt/dq` temperature/humidity, tendencies such as `dudt`, `dls` land–sea mask, `dalb` albedo |
| prefix `a` | time-accumulated diagnostic (for output) | `aprl/aprc/aprs` precipitation, `ashfl/alhfl` fluxes, `acc` cloud cover |
